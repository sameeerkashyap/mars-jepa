# A bounded Dreamer experiment for Mars heating control

Research decision for [Choose a bounded small-data Dreamer experiment and tuning strategy](https://github.com/sameeerkashyap/mars-jepa/issues/6), part of [the Dreamer decision map](https://github.com/sameeerkashyap/mars-jepa/issues/2). Reviewed 2026-11-21. No training, data generation, or test evaluation was done for this note.

## Decision

Use a staged experiment with a small set of one-factor comparisons. First check simulator transitions, budget enforcement, and whether scheduling can improve target tracking. Then validate forecasts on new action schedules. Train an actor and critic only after those checks pass. Admit each stage from measured costs and the repaired cumulative ledger. A stage is a ceiling, not a commitment to run every row.

The confirmed task is a 120-sol South-pole winter episode with 12 actions, each held for 10 sols. The scalar heating action is uniform over latitude and lies in [0, 10] W/m². The target is the simulator frost point plus 2 K. Integrated heat must not exceed 300 W/m²·sol, equivalent to a 2.5 W/m² episode mean. These are benchmark choices. No source establishes that this target is attainable or these settings are optimal.

## Evidence and its limits

Original Dreamer learns a latent dynamics model, actor, and value model. It trains behavior by gradients through imagined trajectories, with value estimates for rewards beyond the imagination horizon. Its world model is held fixed during behavior updates. It shows open-loop forecasts separately from reconstructions and studies representation objectives. Those results concern visual control, not this climate task. [Original paper, sections 2–5 and appendix A](https://arxiv.org/pdf/1912.01603).

The authors' original implementation uses Gaussian latent states, 50-step training sequences, imagination horizon 15, model learning rate 6e-4, and actor/value learning rates 8e-5. These are reference settings, not climate recommendations. Its data loop includes random prefill and further policy experience. [Author implementation, configuration and collection loop](https://github.com/danijar/dreamer/blob/master/dreamer.py).

DreamerV3 uses categorical latents, separate dynamics and representation KL terms, and a free-information threshold. This lets model fit and representation regularization receive different gradients. Its robustness results support retaining a stable starting recipe before a large search; they do not identify the best weights, replay ratio, or model size here. [DreamerV3 paper, world model section and robustness ablations](https://arxiv.org/pdf/2301.04104).

TorchRL v0.14.0 `categorical_kl_terms` stops posterior gradients for the dynamics term and prior gradients for the representation term. It sums KL over categories before applying the free-nat floor. The older `categorical_kl_balanced` helper instead clamps per category. These operations are not interchangeable. The release also supplies model, actor, and value losses; continuous reparameterizable actors use gradients through imagined dynamics. [Pinned categorical loss and actor source](https://github.com/pytorch/rl/blob/v0.14.0/torchrl/objectives/dreamer_v3.py). Original-style TorchRL Dreamer losses have their own Gaussian KL and reconstruction conventions. [Pinned original-style loss source](https://github.com/pytorch/rl/blob/v0.14.0/torchrl/objectives/dreamer.py).

Use pinned release source for the implementation contract. Current `main` documentation may describe later APIs. A categorical block-GRU climate agent is a DreamerV3-based adaptation, not an exact reproduction of the original Dreamer experiment.

## Stage 0: readiness and opportunity to improve

Before any learning run, freeze the winter start rule, the South-pole cell set, physics version, spin-up, and observations. Use surface temperatures, supplied sunlight and previous applied heat. Explicitly decide whether elapsed episode time/known season and remaining heat budget are supplied observations; neither should be inferred from hidden simulator state. Recommend exposing elapsed time and remaining budget as known controller bookkeeping. This requires the task-contract decision before implementation.

Required small checks are monolithic versus 12-interval simulator equivalence, identical seeded repeat runs, energy closure, no off-by-one action shift, no future observation access, reset isolation, terminal handling, and heat integration at the simulator substep. Test zero, maximum, alternating and exhausted-budget actions. Preserve one storm realization across the complete episode and matched no-heating control. Verify the initial observation is pre-action and the next observation is after the applied interval. Budget clipping must be identical in truth execution and imagination. Record both requested and applied actions. Check the final partial interval too if later episode lengths change.

Compare no heating, constant 2.5 W/m², a seasonal schedule, and a simple observation-based controller or small fitted-model search controller. Give controllers the same observations and hard heat allowance. Tune their few settings on validation only. Include an explicitly privileged truth-simulator schedule search using hidden simulator state, if needed, to estimate the best demonstrated performance. It is not an eligible equal-information baseline, and a local search is not a proof of an optimum.

For an inexpensive first schedule screen, compare constant heating with three consecutive 10 W/m² action intervals placed at each possible start position. Each pulse spends exactly the full allowance. Add an observation-based threshold controller with budget enforcement. Evaluate on development conditions only. If all schedules stay frost-pinned, inspect heat spent on ice removal and ground coupling as diagnostics, not policy inputs. If a privileged search finds no useful scheduling gain, pause actor/critic work and resolve whether the task should change. Do not silently raise the heat allowance or move the target. If a simple controller already solves tracking, report that result; Dreamer need not win.

## Data and split proposal

The following counts and seed numbers are task hypotheses proposed for a small pilot, not measured requirements. Check them against all existing run manifests before allocation; seed overlap is not acceptable merely because filenames differ. Keep all windows, counterfactual actions, spin-up states and matched controls from one initial-condition/disturbance group in one split.

* Training: propose condition seeds 5000–5023, with a nested first subset 5000–5011.
* Validation: propose 5100–5107, fixed before fitting. Use the same small schedule battery for each condition; report small-sample uncertainty.
* New control test: reserve 5200–5219 in a separate manifest. Do not inspect outcomes or use for normalization, reward tuning, feasibility design or checkpoint choice.
* Initialization seeds: development 101 and 102; final confirmation 201–205. Keep environment, action-schedule, data-subset and neural initialization RNG streams separate. Seeds 9000–9999 remain untouched.

Start with four heating schedules per training condition: no heat, constant 2.5, a full-budget 10 W/m² three-interval pulse with training-only randomized placement, and a budget-feasible randomized piecewise schedule. For the last schedule, draw 12 bounded actions then rescale downward if their sum exceeds 30 W/m²; never rescale upward beyond the action bound. Store actual actions. This gives 48 initial training episodes and at most 96 at the second rung, excluding spin-up and matched controls. At 12 decisions each, that is 576 or 1,152 transitions, not thousands of independent episodes. It may be too small; the point is to measure that cheaply.

Reuse spin-up within a condition to reduce generation cost, while keeping all its schedules in the same split. Keep daily temperatures and sunlight for forecast checks even if agent transitions are every 10 sols. Cover budget exhaustion, late and early pulses, frost-pinned histories, release from frost when achievable, and storm variation. Do not obtain hidden state by fitting normalizers on diagnostics. Do not supply realized future storms or future observations. Any known future astronomical sunlight must have the same explicit availability for all eligible controllers.

Start offline to compare models on identical data. Add policy experience only if validation shows that the learned policy visits poorly covered histories. A possible admitted next batch is one policy episode per existing training condition, retaining the original replay data. Record provenance and repeat validation; do not generate validation episodes from newly selected favorable seeds. Larger episode counts, storm/physics sweeps and offline/online proportions depend on learning curves and generation cost. Do not announce a large dataset size now.

## Bounded experiment matrix

All numeric choices in this table are proposed sensitivities. Each comparison changes one factor from a registered starting configuration. Keep batch size, optimizer, data, initializations and training work fixed unless that factor is the subject. Use at most two concurrent study workers. Do not run the entire optional menu.

| Priority and stage | Admitted comparison | Reason and decision |
| --- | --- | --- |
| 1: forecasts | F0 starting model versus F1 with posterior reconstruction weight 0; keep open-loop loss and KL fixed. Two development initializations each. | Does posterior reconstruction help action-conditioned open-loop forecasts, or mainly its own score? This is a climate objective ablation, not a claim about original Dreamer. |
| 2: forecasts | F0 versus F2 with representation KL weight 0.05 instead of 0.1, dynamics weight fixed at 0.5. Two initializations. | Test whether a weaker bottleneck preserves useful state under sparse data. Read raw KL and entropies, not only floored loss. If diagnostics show a different failure, register the direction before this run rather than scanning weights. |
| 3: data before size | Selected forecast configuration on 48 versus 96 training episodes. Reuse the two development initializations. | Distinguish missing action coverage from optimization/capacity limits. Also report fixed-update results; extra data plus extra updates is not a pure data-size comparison. |
| 4: full agent | C0 imagination horizon 3 versus C1 horizon 6 action intervals, with the same selected world model and two initializations. | Compare 30 versus 60 sols of imagination within a 12-action episode. Longer forecasts may carry ice-memory benefits and larger model errors. Never imagine beyond the terminal step; zero terminal bootstrap. |
| Optional diagnostic, replace rather than append | One capacity, history, learning-rate or replay-ratio comparison below, selected from recorded failure evidence. At most two initializations. | Prevent a hidden grid. Register the diagnosis and candidate before launching. |
| Confirmation | One validation-selected complete-agent recipe, trained under seeds 201–205, versus one validation-selected eligible simple controller on the final episode set. | Final gate, not another tuning rung. All required models must finish and freeze before any new test outcomes are opened. |

F0 uses the existing small categorical dimensions and loss weights, with a new task-specific configuration and trained checkpoints. Use the existing 1e-3 forecaster learning rate as the initial forecast setting. Fit normalization on training only. The forecast readiness score should include South-pole temperature RMSE at 10, 30, 60 and 120 sols, full-field RMSE, and matched intervention-response RMSE under new schedules. Rank on a preregistered validation mean over those South-pole horizons, with full-field and response errors reported as guards. Compare with persistence, linear and small GRU forecasts. Do not promote a reconstruction improvement with worse open-loop response. If the neural forecast fails to beat simple forecasts consistently on validation, repair coverage/model fit before behavior training.

No numerical forecast-error cutoff has been demonstrated. Set any engineering tolerance in kelvin before runs using the 2 K task scale, not by finding a threshold the winner happens to pass. Actor admission also requires the Stage 0 scheduling opportunity and model-based schedule rankings to agree usefully with truth execution on validation. An averaged global RMSE can hide a wrong polar action response.

Diagnostic alternatives, in descending value after the main comparisons:

1. **Memory:** compare 20 versus 40 sols of observed pre-episode history, same rollout duration and loss locations. No heat is applied during warm-up. Or compare belief dimension 72 versus 144, preserving block divisibility and all other sizes. Choose one; do not change context and capacity together.
2. **Stochastic capacity:** compare 4 versus 8 categories, keeping 8 classes and belief 72. This changes parameter count and KL scale; report both and retain the aggregate free-nat semantics. Raw KL near zero, inactive categories or prior/posterior entropy convergence is a warning, not proof of collapse; a deterministic task may need little stochastic information. Do not add larger latent size solely because reconstruction is good.
3. **Learning rate:** if losses oscillate or gradients clip often, compare 1e-3 versus 3e-4 for the model, keeping the same updates. After actor integration, start actor/value learning rates from the original implementation's 8e-5 only as an explicit adaptation hypothesis, not a tuned answer. Do not jointly search all three rates.
4. **Update ratio:** define it as replay transition presentations per new simulator transition, `updates × batch × unroll / newly collected transitions`; also log optimizer steps and total presentations in offline phases, where this denominator is otherwise misleading. Start with one bounded, documented replay pass count; if train error improves while validation worsens, compare that count with half as many presentations. If both keep improving, propose more optimization only with a cost estimate. Never confound more replay with more unique data.

For 10-sol transitions, use full 12-transition training episodes with an explicit observation burn-in, loss mask and reset mask. Do not copy the visual agent's 50-step sequence blindly. A sequence-length sensitivity can compare 6 versus 12 transition loss windows, retaining the same burn-in and matching presentations. Treat this as the optional diagnostic, not another mandatory axis. A daily model wrapped for 10-sol actions and a native 10-sol model are separate designs; settle that seam before implementing these comparisons.

For the full agent, specify the reward from tracking error, learned reward head, terminal continuation, actor and critic objectives, budget projection and latent bookkeeping before C0. A natural task hypothesis is reward equal to negative area-weighted daily squared tracking error accumulated over each interval. Report physical tracking scores regardless of reward scaling. Keep entropy coefficient, return target, discount and reward scale fixed across the two horizons. Verify imagined returns against simulator returns on validation to detect model exploitation. A complete agent includes real collection and replay, observation updates, imagined rollouts, actor/value updates, and executed evaluation; a frozen decoder plus an action search is a useful baseline but does not complete Dreamer.

## Search method and cost admission

Prefer the causal comparisons above to Latin sampling or random search. With few affordable trials, jointly changing KL, capacity, history, horizon, and replay obscures the cause of a gain. A Latin design spreads points across bounds but cannot make those bounds justified. Random search becomes useful only after evidence identifies a small continuous search space and measured costs fund replicated candidates. If that later happens, cap it in advance, for example at four validation-only candidates over model learning rate and one KL weight, then confirm a winner independently. That is a later proposal, not part of this pilot.

Do not use successive halving initially. Reconstruction can converge before open-loop dynamics or control; early rankings can favor the wrong model. Use fixed epoch/update ceilings and validation-based early stopping, with the same rule for paired candidates. Consider halving only after short- and longer-run validation rankings agree across the two development seeds. Promotion uses validation, never test. An epoch cap or early stopping is permitted; a Nautilus elapsed-time cutoff is not.

The cumulative allowance is 48 CPU-core-hours and 12 GPU-hours, including prior work. Current accounting was inflated during an outage. **No remaining allowance is asserted here.** Repair charges from Kubernetes pod/container start and finish records; retain original entries, corrected charges, source timestamps and reason. Distinguish requested-resource occupancy from observed utilization. Do not subtract an outage interval unless the evidence shows the workload did not run.

Before each stage, measure a small representative generation and train/evaluation unit. Include spin-up, storage, validation, truth control evaluation, scheduling search and five-seed confirmation. Calculate CPU-core-hours from the recorded/requested core count and elapsed workload duration; GPU-hours from GPU allocation and duration. Record utilization separately. For admission, use conservative upper estimates from observed units plus an explicit contingency, and multiply by all remaining candidate/seed units. Do not treat a smoke fixture as a representative training cost. Reuse completed baseline work only if its task, data, code and metric hashes match.

Launch only if repaired spending plus the whole proposed stage and reserved confirmation/evaluation cost fit both cumulative limits. Otherwise reduce optional candidates or defer the stage with a concrete measured-cost proposal. No job deadlines, timeout wrappers, automatic timed deletion or stopping because an estimate is reached. Running work finishes; budgets decide whether new work starts. A larger run needs its own measured generation, training and evaluation proposal after the gate, with a proposed allowance before launch.

## Validation, final gate and reporting

Propose the following aggregation for the task-contract ticket to ratify **before training**. It is a new control metric, separate from the old forecaster's preregistered intervention-response tests.

For each episode, compute `E = sqrt(mean over 120 daily post-transition samples of sum_i w_i (T_i - target)^2 / sum_i w_i)`, with `i` the fixed South-pole latitude band (`lat < -60 degrees`) and `w_i` its area weights. This penalizes cold and hot deviations. Do not filter cells using future control-pinned labels or drop hard episodes. Record whole-field heating side effects, heat used, target attainment fraction, maximum deviation and violations as secondary measures. The winter start rule must guarantee the intended season and be fixed before any outcome screen.

Select the eligible baseline family and its parameters by mean validation episode RMSE. Give all candidates the same heat cap and observation access; report actual heat use. No heating is a diagnostic. Constant 2.5 and pulse schedules spend the cap; adaptive controllers may spend less, so include achieved-error versus actual-heat context without changing the primary equal-allowance comparison. Select the policy recipe and checkpoint rule on validation only. Do not choose a different baseline on each final episode.

On the final set, for each of five training seeds `s`, calculate the mean episode error `A_s` for deterministic Dreamer execution and `B` for the frozen baseline on identical initial conditions/disturbances. Report `R_s = 1 - A_s/B` and pooled `R = 1 - mean_s(A_s)/B`. If `B` is zero, the relative gate is undefined and a 10% improvement is impossible; resolve the task rather than divide by a small arbitrary constant. Near-zero B should also trigger a practical-error discussion.

Use the conservative reading of “across five seeds”: require `R_s >= 0.10` for all five, report pooled R, and require no action/budget violations, leakage or failed reproducibility checks. Ask the task-contract decision to accept or revise this interpretation before runs. Report a paired hierarchical bootstrap 95% interval for R (10,000 resamples, fixed bootstrap RNG seed 6100), resampling training seeds and matched environment-condition groups independently. Preserve paired episode identities and any schedules sharing a condition. Also report all five values and leave-one-seed-out sensitivity. Five training seeds and a small test set do not guarantee significance; a wide interval limits a scale claim even if the point gate passes.

Freeze source archive/hash, config, dependencies (including torch/TorchRL/TensorDict and device), data/split hashes, normalization, seed streams, reward/metric definitions, controller parameters, checkpoint rule and every selected checkpoint before test access. Save full learning curves and candidate failures. Verify freeze hashes on load. Evaluate each frozen seed once on the final set; do not tune against those outcomes. Stochastic policy/model rollouts are a separately labelled uncertainty check with fixed sampling seeds; they do not replace deterministic policy execution. A failed final gate is a negative result. A changed recipe needs a new declared study and fresh holdout, not repeated use of the same gate.

## Decisions that remain

The task contract must settle season/start and warm-up rules, time/budget observations, daily versus 10-sol world-model transitions, metric aggregation and five-seed interpretation. Readiness must establish simulator equivalence, target/scheduling opportunity and repaired compute charges. Costs determine which optional rows fit. Learning curves determine whether more unique episodes, better action coverage, more optimization or more memory is justified. None of these should be guessed from published visual-control benchmarks.

Skipped: production changes, data generation, jobs, checkpoint/test access and claims of a successful control policy. Risk: the heat allowance may leave little useful scheduling gain; sparse episodes may not identify hidden ice memory, and five seeds may leave large uncertainty.
