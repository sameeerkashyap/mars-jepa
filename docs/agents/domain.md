# Domain docs

Use a single context for this repository:

- `GLOSSARY.md` at the repository root defines domain terms.
- `docs/adr/` holds architecture decision records (ADRs). An ADR records a design decision and its reason.

Before exploring the code, read the glossary and ADRs that apply to the work. If a root `GLOSSARY-MAP.md` exists later, follow its links to relevant glossaries.

If these files do not exist, proceed. Create them through the domain-modeling skill when terms or decisions are resolved.

Use glossary terms in issues, code, tests, and explanations. Note unresolved terms for domain modeling. If a proposed change conflicts with an ADR, name the ADR and explain why it should be reconsidered.
